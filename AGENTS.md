# Audren — Repository Agent & Engineering Rules

Standalone open-source repository for the **Audren** zero-crank Solana shielded protocol (`v1.3.0`), BN254 Groth16 circuit & WASM prover, published IDLs, four standardized Apache-2.0 SDKs (Rust, TypeScript, Swift, Kotlin), self-hostable Privacy Relayer, and Web App.

## Workspace boundaries

- **`crates/audren-core/`** is `#![no_std]` with zero dependencies and is the single source of truth for `PROTOCOL_VERSION = 1`, all 12 canonical PDA seeds (`audren_*`, including `audren_roots` -> `249YJTuRtiKAnh346Tc18kF9bHrktdrTzyJMtvUKUgC7` bump `254`), 8 account layouts (`AUD1*`, including `GlobalRootHistory` `AUD1RT01` `10,216 B`), 9 instruction tags (`0x00..=0x08`, `Tag 4 = InitRootHistory`), calibrated tight CU limit constants, proof/memo wire lengths (`192 B` Groth16, `72 B` versioned ciphertext / `106 B` SoA memo, `96` notes/page = `10,240 B`), `audren/v1/*` domain separators, and 33 `AudrenError` codes (`6007 = InvalidRootRing`, `6008 = RootIndexOutOfBounds`, `6009 = RootHistoryMismatch`).
- **`crates/audren-circuits/`** owns the frozen BN254 Groth16 `JoinSplit4AryCircuit` (`17,861` R1CS, `2^15` FFT domain, 4-ary Depth-20 global MASP, 16-lane-capable), deterministic `gen_vk` / `--dump-ts-poseidon` generators, and the `wasm32-unknown-unknown` `extern "C"` prover compiled to `audren_circuits.wasm` (`2.4 MB`).
- **`program/`** is an isolated `#![no_std]` `pinocchio 0.11.1` sBPFv3 program manifest excluded from the root Cargo workspace so sBPFv3 dependencies never collide with host crates (`ark-groth16`, `litesvm`). Always check both manifests independently.
- **`tests/mock-router/`** and **`tests/mock-hook/`** are isolated `#![no_std]` `pinocchio 0.11.1` sBPFv3 programs used by `litesvm_e2e` to test adversarial `ExecViaEscrow` target routers and Token-2022 `TransferHook` execution.
- **`crates/client/`** provides the Rust SDK (native Groth16 prover, BIP-350 Bech32m `aud1...` addresses rejecting non-canonical `spend_pk` and low-order X25519 `view_pk` points, zero-indexer `CompactWalletStore`, Rendezvous HRW privacy-first ordinary Solana RPC scanner, `GlobalRootHistory` snapshot selection & uniform batched witness reconstruction, zero-crank auto-`OpenPage` planning, fallible `try_*` + unified `Deposit` / `InitRootHistory` / `Transact` / `ExecViaEscrow` / `UpdatePool` builders, calibrated CU helpers, deterministic `DefiSessionKeypair`, Mode 1 `SelectiveDisclosureProof`, Mode 2 `FullViewingKey`, and LiteSVM suites).
- **`crates/audren-ffi/`** is the zero-panic UniFFI native FFI facade (`52` exported functions returning typed `Result` errors) over `crates/client` generating the Swift (`packages/swift/`) and Kotlin (`packages/kotlin/`) mobile SDKs with zero cryptographic re-implementation drift, plus the real-sBPFv3 cross-SDK LiteSVM integration suite (`cross_sdk_litesvm`).
- **`spec/test-vectors.json`** is the single canonical cross-language conformance suite verified byte-for-byte by Rust (`audren-client` & `audren-ffi`), TypeScript (`@audren/sdk` & `@audren/sdk/prover`), Swift (`AudrenSDK`), and Kotlin (`xyz.audren.sdk`) on every CI run.
- **`idl/`** owns deterministic Codama v1.8.0 and Anchor v0.30+ IDL generation (`idl/generate-idl.py`) and zero-drift verification (`idl/verify-idl.py`), mirrored into `packages/sdk/`.
- **`packages/sdk/`** is the unified TypeScript ESM SDK: `@audren/sdk` (zero-WASM core with pure-TS Circom BN254 Poseidon, RFC 8439 ChaCha20-Poly1305 with `34 B` AAD + X25519 low-order rejection, Bech32m `aud1...` addresses, 12 PDAs, `GlobalRootHistory` & account layouts, `CompactWalletStore`, `fetchGlobalRootHistory` / `selectRootSnapshotForNotes`, `planAutoOpenPages` / `buildAutoOpenPageInstructions`, calibrated CU helpers, relayer client, Transaction v1 `0x81`, and IDLs) and `@audren/sdk/prover` (`audren_circuits.wasm` Groth16 prover shared directly with `apps/web`).
- **`packages/swift/`** is the SwiftPM SDK (`AudrenSDK`) for iOS 15+ and macOS 13+ backed by `crates/audren-ffi`.
- **`packages/kotlin/`** is the Gradle/JNA Kotlin SDK (`xyz.audren.sdk`) for Android API 24+ and JVM 21+ backed by `crates/audren-ffi`.
- **`apps/relay/`** is the standalone, open-source, self-hostable, zero-crank Cloudflare Worker Privacy Relayer. See [`apps/relay/AGENTS.md`](apps/relay/AGENTS.md).
- **`apps/web/`** is the Next.js 16 + Cloudflare Worker web app, live Wallet Vault, and browser WASM Sandbox. See [`apps/web/AGENTS.md`](apps/web/AGENTS.md).

## Mandatory protocol invariants

1. **Byte-for-byte wire parity across all layers:** Any change to account offsets, PDA seeds, transcript domain separators, instruction tags, CU limit constants, or proof/memo layouts in `crates/audren-core/` or `program/src/` must match `idl/` (re-run `python3 idl/generate-idl.py && python3 idl/verify-idl.py`), `crates/client/`, `packages/sdk/`, `apps/relay/src/solana/`, and `apps/web/lib/`. Keep `JUPITER_CPI_EXCLUDED_DEXES` synced verbatim across `crates/client/src/router.rs`, `packages/sdk/src/swap.ts`, `apps/relay/src/aggregators/jupiter.ts`, and `apps/web/worker/index.ts`. Keep `packages/sdk/wasm/audren_circuits.wasm` & `apps/web/public/wasm/audren_circuits.wasm` AND `packages/sdk/wasm/audren_joinsplit.pk` & `apps/web/public/wasm/audren_joinsplit.pk` byte-identical.
2. **Escrow custody isolation (`ExecViaEscrow`, Tag 6) & atomic WSOL unwrap (`Transact`, Tag 5):**
   - `NullifierPDA` is created before the external DeFi CPI and appended to `NullifierPage`.
   - `vk_id`, `router_prog`, `router_accounts` hash (normalized with Solana transaction-wide writability promotion across `escrow_pda`, `relayer_fee_recipient`, and `extra_writable_pubkeys`), `router_ix_data`, `relayer_fee`, `fee_on_output`, `relayer_fee_recipient`, `min_amount_out`, `out_stealth_owner`, `out_blinding`, and `72 B` `AUD1DYN1` dynamic XOR-masked memo bytes are bound inside the SHA-256 `ctx_hash`.
   - `vault_auth` and `payer` are never signers on the external CPI; only the selected `escrow` shard PDA (`0..16`) signs.
   - No Audren program, `PoolState`, `GlobalRootHistory`, `LaneTreeState`, pages, `NullifierPDA`, or custody vault may appear in `router_accounts`.
   - `escrow` and canonical escrow token accounts (`validate_canonical_ata`) pass pre- and post-CPI owner, delegate, `close_authority`, lamport non-drain, and net slippage (`actual_out >= min_amount_out`) checks; `EXEC_FLAG_FEE_ON_OUTPUT` deducts relayer fee atomically from output proceeds after CPI. Both `!unwrap_wsol` `Transact` withdrawals and `ExecViaEscrow` input legs enforce post-transfer vault validation, exact outflow delta checks, and anti-aliasing rejecting `recipient`/`relayer_fee_recipient` collisions with `nf0`/`nf1`/`vault_ata` or `vault_auth`-owned ATAs.
   - `Transact` (`Tag 5`, `ASSET_MODE_PUBLIC`) with `WITHDRAW_FLAG_UNWRAP_WSOL` initializes an ephemeral 1-shot `audren_unwrap` PDA (`["audren_unwrap", pool_id_le4, nf0_32]`), transfers WSOL from `vault_auth`'s canonical WSOL ATA, closes `audren_unwrap` atomically to `payer` (refunding temporary rent + WSOL lamports), and transfers exact `amount_out` SOL to `recipient` and optional `relayer_fee` SOL to `fee_recipient` in the same instruction (preserving full-exit pause bypass and read-only `GlobalRootHistory` at account `[2]`).
3. **Unified SOL=WSOL custody, Token-2022 solvency & hook isolation:** Unified `Deposit` (`Tag 3`) handles both Native SOL (`DEPOSIT_FLAG_NATIVE_SOL` via `SyncNative` into the canonical `vault_auth` WSOL ATA) and SPL / Token-2022 deposits. Both `Deposit` and `ExecViaEscrow` enforce canonical vault ATAs and commit the measured net vault balance delta (`after - before > 0`) so fee-on-transfer (`TransferFeeConfig`) deposits are never credited above the measured net receipt. Token-2022 TLV inspection is gated strictly on `TOKEN_2022_ID`, and transfer-hook mints execute safely with `is_signer` cleared and Audren custody accounts filtered from trailing accounts (preserving `SYSTEM_PROGRAM_ID` in economy 1-input mode).
4. **16-lane-capable global MASP, inline `GlobalRootHistory`, zero-crank auto-`OpenPage` & governance (`Tag 1` / `Tag 2` / `Tag 4` / `Tag 8`):** The frozen `JoinSplit4AryCircuit` supports 16 lanes (`DEPTH = 20`, 4-ary); `PoolState` starts with `active_lanes = 4` and expands monotonically (`4 -> 8 -> 16`) via `InitLane` without modifying the circuit or breaking historical `GlobalRootHistory` spendability, scaling global tree capacity to `4^20` (`1.099T` notes), isolating per-lane page rollovers (enabling 4-merge Tx v1 batches across distinct lanes), and parallelizing read-only full exits. Unified canonical `vault_auth` ATAs and canonical `NullifierPDA`s are shared across all lanes. Every note-appending `Deposit`, `Transact` (`output_mask != 0`), and `ExecViaEscrow` write-locks the single `GlobalRootHistory` PDA (`accounts[2]`, `10,216 B`, `AUD1RT01`, dual ring: `128`-entry recent `slot_ring` retaining `64–128` active slots / `~13.8s–27.5s` under saturation + `89`-entry stable `epoch_ring` retaining `>= 2,848` slots / `>= 10.2m` with zero idle wall-clock expiry) inline for instant spendability on confirmation (`~400ms` today; `~150ms` under Alpenglow) with zero cranks (`InvalidRootRing = 6007`, `RootIndexOutOfBounds = 6008`, `RootHistoryMismatch = 6009`); `Transact` full exits (`output_mask == 0`) lock `GlobalRootHistory` read-only with zero global write-lock contention. `InitRootHistory` (`Tag 4`) performs authority-gated one-shot migration on existing pools. Wallets and relayers prepend idempotent `LaneRentVault`-funded `OpenPage` (`Tag 2`) pre-instructions at rollover or `>= 90%` lookahead. `UpdatePool` (`Tag 8`) keeps `root_epoch_interval` immutable after initialization (updating `note_rent_fee` and `nf_rent_fee`), supports 2-step authority transfer (rejecting `AcceptAuthority` once renounced), and allows permanent authority renouncement (forbidden while paused).
5. **Solana Transaction Version 1 (`0x81`, `4,096 B`) & Calibrated Tight CU Limits:** Every instruction including `Transact` (`192 B` proof) and `ExecViaEscrow` fits comfortably in a single Solana Transaction v1 (`0x81`) with inline `TransactionConfig` and calibrated tight CU limits (`45k` InitPool, `75k` InitLane / InitRootHistory, `40k` OpenPage, `75k` Deposit / `140k` T22 Hook, `165k` Full Exit, `255k` Withdraw / `295k` T22 Hook, `235k` Private 2in/3out, `285k` base `ExecViaEscrow` + router CPI).
6. **sBPFv3 runtime & Pinocchio discipline:**
   - Keep `program/`, `tests/mock-router/`, and `tests/mock-hook/` `#![no_std]` on `pinocchio 0.11.1` with zero `serde`/`bincode`/`core::fmt` overhead.
   - Keep `rent_minimum_balance` reading raw `SysvarRent` (`lamports_per_byte_year` + `exemption_threshold` via pure-integer `u128` exact IEEE-754 binary64 emulation of Agave's `Rent::minimum_balance`) so pre- and post-SIMD-0194 / SIMD-0437 clusters compute exact rent exemption with zero floating-point ops, and keep the `>= 1` lamport zero-rent floor on `create_pda_safe` and `OpenPage` so no Audren PDA can ever be reaped on a zero-rent cluster.
   - Keep large CPI/verifier stack buffers `#[inline(never)]` and place scratch regions in disjoint compile-time-checked slices of Solana's `32 KiB` SBF heap (`pinocchio::no_allocator!()`, zero `liballoc`) well under Solana's `4,096 B` stack frame limit.
   - Every on-chain account (`SubtreePage` `8,256 B`, `SubtreeRootPage` `9,664 B`, `MemoPage` `10,240 B`, `NullifierPage` `9,664 B`, `GlobalRootHistory` `10,216 B`) stays within Solana's `10,240 B` CPI allocation limit with zero `realloc`.
